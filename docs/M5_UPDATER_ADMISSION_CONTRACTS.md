## Independent literal subjects

The fixtures construct exactly21 named files using the published field order,
fixed fictional release18/schema13/source/image/container identities,24 unique
ordered workspace asset paths and their corresponding digests, and a complete
24-step sealed CI record. The proposed generation is1, independently of the
artifact ordinal18 and tool source20. Hashes are calculated by the fixture's own
SHA256 caller; parser or report output does not supply expected record values.

Dependency hashes follow the explicit acyclic schema. A negative semantic fixture
can reseal only the changed file's parent hash references, preserving the bad
subject value and all other identities. This prevents an early stale-checksum
failure from masquerading as proof of a semantic cross-record check. Raw archive
or opaque-leaf tampering without resealing is tested separately.

Existing manifest/image/recovery proofs use their actual producer shapes.
Their original bytes may use compact or pretty JSON. New records remain compact
ordered ASCII with closed fields; the explicit manual projection alone ends in
exactly one LF. Manifest/top-level workspace contracts are `reborn-workspace-v1`;
image nested identity and source qualification use `reborn-auth-v1`.
Compiled package_version0.1.0 is distinct from release version0.1.18.

The fake ZIP and tar are deliberately opaque fictional byte fixtures. No test
calls a valid local checksum an archive extraction, containment proof, Docker
inspection or renewed GitHub authentication. Both actual files must be present
and rehashed under the published byte limits.

## Frozen outcome and refusal matrix

| Boundary | Independent expected outcome |
| --- | --- |
| Complete fixture | Actual CLI and library admit only diagnostic agreement, report explicit fixture trust and all effects/adoption/execution flags false, and leave every input unchanged. |
| Root trust mode | Explicit Fixture always reports same-uid-fixture even under EUID0; default RootSealed requires EUID0/root ownership. Neither mode authenticates invented history. |
| Canonical encoding | Matching external digests do not admit reordered keys, whitespace/newline, escapes, unknown/duplicate fields, alternate integer encoding or malformed IDs/hashes in new records. |
| Producer bytes | Properly bound pretty producer JSON is admitted; duplicates/unknown fields, bad types, contract/package mismatch or false required recovery flags refuse. |
| Release agreement | Every envelope source/tree/version/ordinal/channel/schema/platform/image/binary/archive/qualification/CI/artifact/hash subject must agree with the exact fixed evidence. |
| Assets and CI | Exactly24 unique ordered paths/digests and24 correctly numbered ordered successful step records are required; no sorting, deduplication, missing-step or truncated evidence success. |
| Opaque leaves | Nonempty bounded arbitrary bytes are acceptable when consistently sealed. No generic manual-state/policy/inventory parser is invented. Unsealed byte changes refuse even with the same projection. |
| Current artifact | Admission, manifest, projection, binding and observation name the current artifact. A future or different target is outside this profile. |
| Proposed authority | Generation1/manual-only/proposed/absent-adopted-authority/no-unresolved-work claims are mandatory. No diagnostic performs the transition or rewrites a selector/journal. |
| Sealed assessment | Boot, observer, app/PG birth/CIDs/images, network, lock and protected-inventory bindings agree; age0 and exactly60seconds are accepted within that context, future observation/60seconds+1 refuses. This is not a live clock admission. |
| Files and paths | Missing/extra files, directories, unsafe modes/UID/link/type, symlinked ancestry, hardlinks, FIFOs, changed held root/file identity and over-limit archives refuse. No recursive traversal or outside-file read/write. |
| Privacy and no effects | Success/refusal leaves bundle and pseudo-production bytes untouched. Errors contain only the fixed sanitized refusal; no path or private payload escapes. |

The public descriptor API supplies a deterministic substitution seam:
`Bundle::open` followed by fixture-controlled root/file replacement and
`revalidate` must refuse. This exercises real descriptors and filesystem state,
not a production test hook or a copied implementation policy.

No-effects snapshots include file bytes, entry names/types, ownership, modes,
inode/link identities and modification/change times; read access times are not
treated as writes. CLI subprocesses use an owned-child pidfd with a native
bounded wait, including the real FIFO refusal case.
